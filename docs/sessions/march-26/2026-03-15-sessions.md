**Conversation marker:** `41536493-114c-4979-95c0-f00a54e0cc1f`
**Project:** ytm-player

**What happened:** Built a cmux sidebar integration to show now-playing and up-next track info. Started with a background bash polling script approach, debugged multiple issues (wrong $TMPDIR, missing `timeout` on macOS, CMUX_WORKSPACE_ID not passed to background processes), then pivoted to a much better native approach — a `CmuxService` built directly into the player that fires on track change events. Also merged upstream v1.5.1 (multi-account auth fix, browse notification fix) and added diagnostic logging for an intermittent auth issue.

**Key decisions:**
- Native CmuxService over polling script — Shawn suggested it; event-driven is instant, zero overhead, no cleanup headaches
- `asyncio.create_subprocess_exec` over `subprocess.run` — non-blocking in async context
- Activate only when `CMUX_WORKSPACE_ID` is set — zero-cost when not in cmux
- Set ytm-now pill before ytm-next — controls sidebar ordering (now-playing on top)
- No pause/resume awareness — track changes only, keeps it simple

**Open questions:**
- Intermittent auth failure on macOS — `com.apple.provenance` quarantine xattr suspected but not confirmed. Diagnostic logging added to catch it next time.
- Media keys accessibility permission warning — separate issue, needs terminal app added to System Settings > Accessibility
